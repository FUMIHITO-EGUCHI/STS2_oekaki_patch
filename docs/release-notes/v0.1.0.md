# v0.1.0

## 概要

導入方式を `sts2.dll` を改変しない ModManager 経由に切り替え、マルチプレイ同期と、エンドユーザー向けのドラッグ&ドロップ導入を追加したリリース。

## ユーザーにとって良くなったこと

- **Steam 整合性チェックに引っかからない導入方式**: `sts2.dll` を改変せず、`<game>/mods/EraserMod/` に DLL と `manifest.json` を配置するだけになった。ゲームをアップデートしても再導入不要。
- **マルチプレイ同期**: MOD を入れた peer 同士なら、相手の描画にも鉛筆色・太さが反映される。`Ctrl+Z` の Undo も相手側に伝わる。MOD 未導入の peer とも引き続き接続可能（その peer の見た目はバニラ動作）。
- **ドラッグ&ドロップ導入**: `install.bat` / `uninstall.bat` をダブルクリックでデフォルト Steam パスへ導入、または **ゲームフォルダを bat にドラッグ&ドロップ** で非標準パスにも対応。PowerShell を意識する必要なし。
- **旧 Injector 方式からの自動移行**: v0.0.1 で導入していた場合、新しい `install.bat` 実行時に `sts2.dll` を `sts2.dll.orig` から自動復元し、旧 `EraserMod.dll` を取り除く。

## 詳細

v0.0.1 は `<Module>.cctor` に IL 注入で `Bootstrap` 起動を仕込む方式だった。Steam の整合性チェックを誘発しやすく、ゲーム更新のたびに再注入が必要だった。

v0.1.0 ではゲーム公式の `MegaCrit.Sts2.Core.Modding.ModManager` 経由のロードに切り替え、`Bootstrap` クラスに `[ModInitializer("Init")]` を付けて `Harmony.PatchAll()` を呼ぶ構造とした。`sts2.dll` には触れないため、Steam 整合性チェックの影響を受けない。

マルチプレイ同期は `Net/` 配下に追加。`z` プレフィックスで vanilla `INetMessage` の後ろにソートされる順序を確保し、MOD 有無に関わらず vanilla 側のパケット ID を維持する設計。
